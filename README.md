เว็บร้านค้าออนไลน์แบบ Full-stack มีหน้าร้านสำหรับลูกค้า และหลังร้านสำหรับผู้ดูแลระบบ

| `server/` | Node.js, Express 5, MySQL 8 (`mysql2`), JWT ใน httpOnly cookie, Cloudinary, Stripe |

## ความสามารถ

**หน้าร้าน (ลูกค้า)**
- หน้าแรก: สไลด์รูปเทคโนโลยี (สุ่มลำดับทุกครั้งที่เปิด), หมวดหมู่, สินค้ายอดนิยม, สินค้าใหม่
- ร้านค้า: ค้นหา + กรองตามหมวดหมู่และช่วงราคา (ใช้พร้อมกันได้ แชร์ลิงก์ได้)
- หน้ารายละเอียดสินค้า (`/product/:id`): รูปหลายรูป (เลื่อนอัตโนมัติ / ปัด / กดลูกศร), เลือกจำนวน, ใส่ตะกร้า / ซื้อเลย
- รายการโปรด: กดหัวใจบนการ์ดหรือหน้ารายละเอียด (ต้อง login) ดูทั้งหมดได้ที่เมนูโปรไฟล์ › รายการโปรด (`/user/wishlist`)
- แจ้งเตือน: กดเพิ่มเกินจำนวนที่มีจะขึ้น "เหลือเพียง X ชิ้น", กระดิ่งแจ้งเตือนเมื่อสถานะคำสั่งซื้อเปลี่ยน, กด "แจ้งเตือนเมื่อสินค้ามีของ" ตอนสินค้าหมด
- ตะกร้า → กรอกที่อยู่ → ชำระเงินด้วยบัตรผ่าน Stripe → ประวัติการสั่งซื้อ
- หน้าเกี่ยวกับเรา, สมัครสมาชิก / เข้าสู่ระบบ (มีแอนิเมชันตอนสลับหน้า)

**หลังร้าน (admin)** — `/admin`
- แดชบอร์ด: ยอดขาย, กราฟรายวัน/รายเดือน, สถานะคำสั่งซื้อ, สินค้าขายดี, สินค้าใกล้หมด
- คำสั่งซื้อ: กรองตามสถานะ, ค้นหา, เปลี่ยนสถานะ
- แบนเนอร์หน้าแรก: อัปรูปสินค้าติดกระแส (เช่น มือถือรุ่นใหม่ การ์ดจอ) ใส่ชื่อ ข้อความ และลิงก์ไปหน้าสินค้า เปิด/ซ่อนได้
- สินค้า / หมวดหมู่: เพิ่ม แก้ไข ลบ อัปโหลดรูป, ตั้งเกณฑ์ "ใกล้หมด" ของแต่ละสินค้า
- กระดิ่งแจ้งเตือน: คำสั่งซื้อรอดำเนินการ + สินค้าใกล้หมด (พร้อมจำนวนลูกค้าที่รอของ)
- ผู้ใช้งาน: เปลี่ยนสิทธิ์, ระงับบัญชี

ทุกหน้ารองรับมือถือ

## การทำงานของแต่ละส่วน

### สไลด์รูปหน้าแรก

- รูปอยู่ที่ [`client/src/assets/hero/`](client/src/assets/hero/) — ตอนนี้มี 14 รูป (AI, VR, หุ่นยนต์, โดรน, สมาร์ตโฟน, ศูนย์ข้อมูล ฯลฯ)
- **สุ่มลำดับใหม่ทุกครั้งที่เปิดหน้า** — ในหนึ่งรอบแสดงครบทุกรูปก่อนจะวนซ้ำ และ**ไม่เริ่มด้วยรูปเดียวกับครั้งก่อน** (จำรูปแรกไว้ในเบราว์เซอร์)
- เลื่อนอัตโนมัติทุก 3.5 วินาที โหลดรูปแรกทันที รูปที่เหลือโหลดตามหลัง

**แบนเนอร์สินค้าติดกระแส (ตั้งจากหลังร้าน)** — หลังร้าน › แบนเนอร์หน้าแรก
- admin อัปรูป (แนะนำ 1600 × 640 px) ใส่ชื่อ ข้อความรอง และเลือกสินค้าที่จะลิงก์ไป → สไลด์แสดงชื่อ ราคา และปุ่ม "ดูสินค้า" คู่กับรูปสินค้า
- **เปลี่ยนชุดทุกวัน** ตามวันที่เวลาไทย: ทุกคนเห็นลำดับเดียวกันในวันเดียวกัน แสดงวันละไม่เกิน 6 รูป (มีมากกว่านั้นแต่ละวันจะได้ชุดต่างกัน) และรูปแรกไม่ซ้ำกับเมื่อวาน — [`client/src/utils/dailyBanners.js`](client/src/utils/dailyBanners.js)
- ยังไม่มีแบนเนอร์ที่เปิดใช้งาน → ใช้**สินค้าขายดีในร้าน** (ที่มีรูป) แสดงแบบเดียวกันแทนอัตโนมัติ — ถ้าร้านยังไม่มีสินค้าเลย จึงใช้รูปเทคโนโลยีด้านล่าง
- ใช้รูปที่ร้านมีสิทธิ์ใช้ (เช่น รูปจากตัวแทนจำหน่าย) — รูปสินค้าของแบรนด์ส่วนใหญ่มีลิขสิทธิ์

**เพิ่ม / เปลี่ยนรูปเทคโนโลยี (สำรอง)** — วางไฟล์ `.webp` `.jpg` หรือ `.png` ลงในโฟลเดอร์ `hero/` แล้วรูปจะขึ้นเองโดยไม่ต้องแก้โค้ด (ลบไฟล์ = เอารูปออก)
- ขนาดแนะนำ **1400 × 560 px** (สัดส่วน 5:2) ไฟล์ไม่เกิน ~150 KB — แนะนำ `.webp`
- ตั้งชื่อไฟล์เป็นภาษาอังกฤษสั้น ๆ เช่น `smart-home.webp` แล้วเพิ่มคำอธิบายรูป (alt) ใน `ALT` ที่ [`client/src/utils/heroImages.js`](client/src/utils/heroImages.js) — ถ้าไม่เพิ่มจะใช้คำว่า "ภาพเทคโนโลยี"
- รูปปัจจุบันมาจาก [Unsplash](https://unsplash.com) ซึ่งใช้ได้ฟรีรวมถึงเชิงพาณิชย์ — รูปที่เพิ่มเองต้องมีสิทธิ์ใช้งาน

### หน้าเข้าสู่ระบบ / สมัครสมาชิก

- ทั้งสองหน้าใช้กรอบเดียวกัน ([`client/src/layouts/AuthLayout.jsx`](client/src/layouts/AuthLayout.jsx))
- กดสลับระหว่าง "เข้าสู่ระบบ" กับ "สมัครสมาชิก" → แผงสีม่วงเลื่อนไปอีกฝั่ง (จอคอม) ฟอร์มเลื่อนเข้า-ออก และข้อความบนแผงเปลี่ยนตามหน้า
- ผู้ใช้ที่ตั้งค่า "ลดการเคลื่อนไหว" (reduce motion) ในเครื่อง จะไม่เห็นแอนิเมชัน
- หน้าสมัครสมาชิกแสดงความแข็งแรงของรหัสผ่าน (`zxcvbn` — โหลดตามหลังเพื่อให้หน้าเปิดเร็ว)

### ขั้นตอนการสั่งซื้อ

1. **เพิ่มลงตะกร้า** — เก็บในเบราว์เซอร์ (ยังไม่ต้อง login)
2. **ดำเนินการสั่งซื้อ** (ต้อง login) — ส่งตะกร้าไป server ซึ่งตรวจสต็อกและ**คิดราคาจากฐานข้อมูล**
3. **กรอกที่อยู่** ที่หน้าชำระเงิน
4. **ชำระเงิน** — server สร้างรายการกับ Stripe ตามยอดตะกร้า ลูกค้ากรอกบัตรผ่าน Stripe โดยตรง (ข้อมูลบัตรไม่ผ่าน server เรา)
5. **บันทึกคำสั่งซื้อ** — server ถาม Stripe ว่าชำระสำเร็จจริงและยอดตรง แล้วสร้างคำสั่งซื้อ ตัดสต็อก เพิ่มยอดขาย และล้างตะกร้าในคราวเดียว (ถ้าของหมดพอดีจะคืนเงินอัตโนมัติ)
6. **ติดตามสถานะ** — ลูกค้าดูที่ "ประวัติการสั่งซื้อ" admin เปลี่ยนสถานะได้ที่หลังร้าน: รอดำเนินการ → กำลังดำเนินการ → สำเร็จ / ยกเลิก
7. **ลูกค้ายกเลิกเอง** — ทำได้เฉพาะตอน "รอดำเนินการ" → คืนสต็อก ลดยอดขาย และคืนเงินเข้าบัตรผ่าน Stripe ในคราวเดียว (คืนเงินไม่สำเร็จ = ไม่ยกเลิก) คำสั่งซื้อที่คืนเงินแล้ว admin เปลี่ยนสถานะไม่ได้

### การแจ้งเตือน

| ใคร | แจ้งเรื่อง | ทำงานอย่างไร |
|---|---|---|
| admin | สินค้าใกล้หมด | แต่ละสินค้าตั้ง **"แจ้งเตือนเมื่อเหลือไม่เกิน (ชิ้น)"** ในฟอร์มสินค้าได้ (ค่าเริ่มต้น 5, ใส่ `0` = ไม่แจ้ง) — คงเหลือ ≤ เกณฑ์ จะขึ้นที่กระดิ่งหลังร้าน, แดชบอร์ด และตัวกรอง "ใกล้หมด" ในหน้าสินค้า |
| admin | คำสั่งซื้อรอดำเนินการ | นับที่กระดิ่งหลังร้าน กดแล้วไปหน้าคำสั่งซื้อที่กรองไว้ |
| ลูกค้า | กดเกินจำนวนที่มี | กดใส่ตะกร้า / ปุ่ม + (การ์ดสินค้า, หน้ารายละเอียด, ตะกร้า) เกินสต็อก → ขึ้น "[ชื่อสินค้า] เหลือเพียง X ชิ้น" และไม่เพิ่มให้ |
| ลูกค้า | สถานะคำสั่งซื้อเปลี่ยน | admin เปลี่ยนสถานะ → server บันทึกแจ้งเตือนในตาราง `notification` → ขึ้นที่กระดิ่งของลูกค้า |
| ลูกค้า | สินค้ากลับมามีของ | สินค้าหมด → ลูกค้า (login แล้ว) กด "แจ้งเตือนเมื่อสินค้ามีของ" (เก็บในตาราง `restockalert`) → admin เติมสต็อก → ทุกคนที่รอได้แจ้งเตือน แล้วรายการรอถูกลบ |

- กระดิ่งโหลดใหม่ทุกครั้งที่เปลี่ยนหน้า และทุก 1 นาที — กดรายการแล้วไปหน้าที่เกี่ยวข้องและนับว่าอ่านแล้ว มีปุ่ม "อ่านทั้งหมด"
- ไม่ได้ส่งอีเมล แจ้งเตือนอยู่ในเว็บเท่านั้น

### รูปสินค้า

- admin อัปโหลดรูปในฟอร์มสินค้า → หน้าเว็บย่อรูปเหลือไม่เกิน 720 px → อัปขึ้น **Cloudinary** → เก็บลิงก์รูปไว้ในตาราง `image`
- ลบสินค้า → ลบรูปบน Cloudinary ด้วย (สินค้าที่อยู่ในตะกร้าหรือเคยถูกสั่งซื้อแล้วลบไม่ได้ เพื่อเก็บประวัติ)

## ติดตั้งและรันครั้งแรก

**สิ่งที่ต้องมี:** Node.js 20.12 ขึ้นไป (แนะนำ 22+), MySQL 8, บัญชี [Cloudinary](https://console.cloudinary.com) (อัปโหลดรูป) และ [Stripe](https://dashboard.stripe.com/test/apikeys) แบบ test mode (ชำระเงิน)

### 1. สร้างฐานข้อมูล

ใน MySQL Workbench (หรือ `mysql` command line):

```sql
CREATE DATABASE ecom CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

แล้ว import [`server/db/schema.sql`](server/db/schema.sql) — Workbench: **Server › Data Import › Import from Self-Contained File** เลือกไฟล์นี้ และเลือก schema `ecom`

```bash
# หรือใช้ command line
mysql -u root -p ecom < server/db/schema.sql
```

### 2. Backend

```bash
cd server
npm install
cp .env.example .env        # แล้วแก้ค่าใน .env ให้ถูกต้อง (ดูหัวข้อ "ตัวแปรสภาพแวดล้อม")
npm run seed                # สร้างบัญชีผู้ดูแลระบบ
npm start                   # รันที่ http://localhost:8000
```

### 3. Frontend (เปิดอีกเทอร์มินัล)

```bash
cd client
npm install
npm run dev                 # รันที่ http://localhost:5173
```

เปิดเบราว์เซอร์ที่ **http://localhost:5173**

## ฐานข้อมูล

ใช้ **MySQL 8** ผ่าน package `mysql2` เขียน SQL ตรง ๆ ใน `server/controllers/` — เปิดดูและแก้ข้อมูลได้ใน **MySQL Workbench**

| ตาราง | เก็บอะไร |
|---|---|
| `user` | ผู้ใช้ (รหัสผ่านเข้ารหัสด้วย bcrypt), สิทธิ์, สถานะ, ที่อยู่ |
| `category` / `product` / `image` | หมวดหมู่, สินค้า, รูปสินค้า (ไฟล์จริงอยู่บน Cloudinary) |
| `cart` / `productoncart` | ตะกร้าของลูกค้าแต่ละคน |
| `order` / `productonorder` | คำสั่งซื้อ และรายการสินค้าในคำสั่งซื้อ |
| `notification` / `restockalert` | แจ้งเตือนของลูกค้า และรายการ "รอสินค้ามีของ" |
| `wishlist` | สินค้าที่ลูกค้ากดหัวใจไว้ |
| `banner` | แบนเนอร์หน้าแรก |

**แก้โครงสร้างตาราง** (เพิ่มคอลัมน์/ตาราง)
1. แก้ใน Workbench
2. แก้ SQL ใน `server/controllers/` ให้ตรงกัน
3. ส่งออกโครงสร้างใหม่เป็น `schema.sql` สำหรับติดตั้งครั้งต่อไป
4. ถ้ามีฐานข้อมูลอื่นที่ต้องอัปเดตตาม ให้เขียนคำสั่ง `ALTER TABLE` เก็บไว้ใน `server/db/migrations/` (ตั้งชื่อเรียงลำดับ เช่น `007_xxx.sql`)

```bash
mysqldump -u root -p --no-data --skip-comments ecom > server/db/schema.sql
```

**ฐานข้อมูลที่ติดตั้งจาก `schema.sql` รุ่นเก่า** ให้รันไฟล์ใน [`server/db/migrations/`](server/db/migrations/) ตามลำดับเลข (ติดตั้งใหม่จาก `schema.sql` ปัจจุบันไม่ต้องรัน)

| งาน | Workbench | คำสั่ง |
|---|---|---|
| สำรอง | Server › Data Export | `mysqldump -u root -p ecom > backup.sql` |
| กู้คืน | Server › Data Import | `mysql -u root -p ecom < backup.sql` |

เก็บไฟล์สำรองไว้ใน `server/backup/` ได้ (โฟลเดอร์นี้ไม่ถูก commit เพราะมีข้อมูลผู้ใช้)

> **เวลาในฐานข้อมูลเป็น UTC** (เวลาไทย = UTC + 7) ตอนเพิ่มข้อมูลเองใน Workbench ให้ใช้ `UTC_TIMESTAMP(3)`
> **ยอดเงิน:** `cartTotal` / `price` เป็นบาท ส่วน `order.amount` เป็นสตางค์ (ยอดที่ Stripe ตัดจริง)

| `CLIENT_URL` | | หน้าเว็บที่อนุญาตให้เรียก API คั่นหลายที่ด้วย `,` (ค่าเริ่มต้น `http://localhost:5173`) |

| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | | บัญชีที่ `npm run seed` สร้าง |

## การเข้าสู่ระบบและความปลอดภัย

**Token เก็บใน httpOnly cookie**
- login สำเร็จ server จะส่ง cookie ชื่อ `token` (JWT) — JavaScript บนหน้าเว็บ**อ่านไม่ได้** จึงถูกขโมยผ่าน XSS ไม่ได้
- **อายุการ login:** ไม่ใช้งานเกิน **2 ชั่วโมง** → หมดอายุ / ยังใช้งานอยู่ → server ต่ออายุ cookie ให้เอง (ต่อได้รวมไม่เกิน **1 วัน** นับจากตอน login) — การเช็กแจ้งเตือนอัตโนมัติทุก 1 นาทีไม่นับเป็นการใช้งาน (ส่ง header `X-Background`) ปรับค่าได้ที่ [`server/config/authCookie.js`](server/config/authCookie.js)
- หน้าเว็บไม่เก็บ token ใน `localStorage` (เก็บแค่ข้อมูลผู้ใช้สำหรับแสดงผลและตะกร้า)
- cookie หมดอายุ → server ตอบ `401` → หน้าเว็บล้างสถานะ login และพาไปหน้า login อัตโนมัติ
- ออกจากระบบ → server ลบ cookie

**การป้องกันอื่น ๆ**
- **สิทธิ์:** API ที่แก้ไขข้อมูลร้านใช้ได้เฉพาะ admin, บัญชีที่ถูกระงับใช้งาน API ไม่ได้
- **CSRF:** request ที่แก้ไขข้อมูลต้องมาจากหน้าเว็บใน `CLIENT_URL` + cookie เป็น `SameSite=Lax`
- **ราคา:** ตะกร้าคิดราคาจากฐานข้อมูลเสมอ ไม่เชื่อราคาที่ส่งมาจากหน้าเว็บ
- **การชำระเงิน:** server ตรวจกับ Stripe โดยตรงว่าชำระสำเร็จ ยอดตรง เป็นของผู้ใช้คนนั้น และใช้สร้างคำสั่งซื้อได้ครั้งเดียว — ถ้าของหมดระหว่างชำระ จะคืนเงินอัตโนมัติ
- **ฐานข้อมูล:** ทุก query ใช้ parameter (`?`) กัน SQL injection, การสร้างคำสั่งซื้อ/ตัดสต็อกทำใน transaction

**นำขึ้นใช้งานจริง:** ใช้ HTTPS, ตั้ง `NODE_ENV=production`, เปลี่ยน `SECRET` และรหัสผ่าน admin, ตั้ง `CLIENT_URL` เป็นโดเมนจริง
ถ้าหน้าเว็บกับ API อยู่คนละโดเมน (เช่น `shop.com` กับ `api.other.com`) ต้องตั้ง `COOKIE_SAMESITE=none` ด้วย — แนะนำให้อยู่โดเมนเดียวกัน (เช่น `shop.com` กับ `api.shop.com`) จะใช้ค่าเริ่มต้นได้เลย

## แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| หน้าเว็บเป็นสีขาวทั้งหน้า | dev server ค้างหลังติดตั้ง/ลบ package — หยุด `npm run dev` (Ctrl+C) แล้วรันใหม่ ถ้ายังขาวใช้ `npx vite --force` |
| ไม่มีสินค้า / login ไม่ได้ | server ยังไม่รัน หรือ MySQL ปิดอยู่ — ดูเทอร์มินัลของ `server` |
| login ได้แต่เด้งกลับหน้า login | cookie ไม่ถูกส่ง — ตรวจว่า `CLIENT_URL` ใน `server/.env` ตรงกับที่อยู่หน้าเว็บ (รวม port) และเปิดเว็บด้วย `localhost` ไม่ใช่ `127.0.0.1` |
| `Origin not allowed` | เปิดหน้าเว็บจากที่อยู่ที่ไม่อยู่ใน `CLIENT_URL` — เพิ่มที่อยู่นั้นใน `.env` (คั่นด้วย `,`) |
| `User not found or not Enabled` | อีเมลผิด หรือบัญชีถูกระงับ — admin รัน `npm run seed` เพื่อรีเซ็ต |
| อัปโหลดรูปไม่ได้ | ค่า `CLOUDINARY_*` ใน `server/.env` ไม่ถูกต้อง |
| หน้าชำระเงินขึ้น error | `STRIPE_SECRET_KEY` ไม่ถูกต้อง หรือ key ฝั่ง client/server มาจากคนละบัญชี Stripe |
| ลบสินค้าไม่ได้ | สินค้าอยู่ในตะกร้าลูกค้าหรือมีในคำสั่งซื้อแล้ว (เก็บไว้เป็นประวัติ) — ตั้งจำนวนคงเหลือเป็น 0 แทน |
| ไอคอนแท็บยังเป็นอันเก่า | กด Ctrl+F5 เพื่อล้างแคช |
